Suture · 能力清单

给不熟悉技术的同事用的一个本地小程序：双击打开、点一次「开始检查」， 就知道本机的 AI 客户端能不能连上公司网关 AI Gate； 连不上时直接告诉他是哪儿的问题、怎么修，能安全自动修的就给按钮，处理完再测一次。

覆盖三个客户端：Claude Code CLI、Codex CLI、DeepSeek Harness。

交付形态：单个可执行文件（Windows / macOS / Linux，各两种 CPU 架构）， 不用装 Python、不用装任何依赖。

01它怎么判：只看「能不能用」

判定标准只有一条——用客户端自己配的那套配置，真实发一个请求出去，通不通。 刻意不做逐项静态体检：非技术同事要的是「能不能用」，不是「哪里跟规范不一致」。 静态检查降级成「连不上时才跑的诊断器」，健康用户不会看到满屏报错。

已连接 一个绿勾，不罗列任何细节
无法连接 展开「可能的原因」，每条=一句人话+怎么修，挑着处理
未配置 装了但没连网关 → 给配置面板，选模型+填 Key 一步到位
未安装 引导去「安装 / 上手」页，用官方命令直接装

02能发现并自动解决的问题

这些点一下按钮就能修好，改完立刻重测，通不通当场反馈。

能发现的问题做了什么
1地址前后多了空格去掉空格
2协议写成了 http://（网关要求 https）补成 https
3地址少了 https:// 前缀补上前缀
4地址结尾多拼 / 少拼一段 /v1按该客户端的拼路径习惯改对
5地址跟网关登记的不一致改成登记地址
6根本没配网关地址写入网关规范地址
7Key 没放进网关要求的请求头
AI Gate 只认 Token 头，很多人放进了 x-api-key		 自动把 Key 写进 headers.Token / ANTHROPIC_CUSTOM_HEADERS
8Key 前后带了空格或换行（复制粘贴常见）去掉首尾空白
9模型名只差大小写 / 连字符写法（如 GLM-5.3）改成网关登记的写法

第 7 条是实测最有价值的一条：同样一把有效 Key，放进 x-api-key 一律 401，只有放进 Token 头才 200。

以前工具会误导用户「Key 失效了，去后台重新生成」——现在能直接点按钮补上。

04能发现，但只能在工具外处理

给明确说明，不误导用户白点按钮。

能发现的问题告诉用户什么
17配置文件语法错（JSON / TOML / YAML），整层配置不生效 指出文件位置和错误行列，让改完重新检查
并拒绝自动修改，见第 05 节
18文件不是 UTF-8 编码（记事本存成 ANSI/GBK） 说明整份文件读不出来，让另存为 UTF-8
19字段名拼错（写了工具不认识的键，等同没配） 给出最接近的正确字段名
20配置存在但整层不生效（Codex 项目没被标记为可信） 说明「改这一层没用」，指出该改哪一层
21生效值来自系统环境变量（优先级压过配置文件） 说明工具写不到环境变量，让去「系统设置 → 环境变量」改或删
22生效值来自公司统一下发的托管配置（IT 下发、只读） 说明本地改了不生效，请联系 IT
23同一项在多层配置里取值不一致 说明改哪一层、让用户把其它层统一掉
24同一个 Key 在多个位置重复设置、值还不一样 摆出证据（哪个更像网关签发的 Key），让用户确认后删掉多余的
25客户端带不了网关要求的请求头
Codex 只能发 Authorization，无法附加自定义头		 直接说明这条路走不通，建议改用 Claude Code 或 DeepSeek
不引导用户白填 Key
26型号在清单里、地址也对，但网关实际拒绝（型号下线 / 改名） 说明可能已下线，联系网关确认
27请求在本机就没发出去（Key 带换行导致请求头非法等） 点明是本地问题，让先处理下面的本地项
不再误报成「网关侧故障，联系值班人员」

05写配置的四条安全约定

  1. 永远先备份。任何一次写入（修复 / 存 Key / 一键配置）都先备份到 ~/.suture/backups/<时间戳>/，出问题能人工找回。
  2. Key 不出现在界面上。界面、日志、命令行、接口返回里一律只有掩码 （前 4 位 + 后 4 位）；网关抛出的异常原文也不外传（它可能带着请求头的值）。
  3. 读不懂的文件不写。配置有语法错或编码不对时，如实报错并拒绝写入—— 按读空的文件写回会把同一份配置里其它内容（permissions、hooks、其它插件配置） 静默清掉。宁可写不了，也不能悄悄清空别人机器上的配置。
  4. 写不进去的不给按钮。生效层是环境变量或托管配置时，自动修复写了也不生效， 这种不给「修复」按钮（避免用户点了没反应、原地打转），只给说明。

06它不负责什么

  • 不判断「是不是直连网关」——只要真实请求能通就判已连接。客户端把地址指向 一个本地转发服务、请求返回 200 时也算通；口径是「能不能用」，不是「有没有按规范配」。
  • 不比对公司规范——不做配置项的合规审计，不检查「有没有多余字段」这类问题。
  • 不改系统环境变量——环境变量层面的配置只给指引。
  • 不代管 Key——Key 只在用户自己的机器上流转，不回传、不上报。
  • 网关规则靠内置快照——型号清单更新目前需要更新规则文件重新分发 （网关尚未提供可拉取的型号接口）。
